# jobcan-agent

[English](README.md) | **日本語** | [Português](README.pt.md)

> **非公式プロジェクトです。** 株式会社DONUTS(ジョブカンの提供元)とは一切関係ありません。

AI エージェント(Claude、ChatGPT など)からジョブカン勤怠管理を操作できるようにします。休暇の申請、
残日数の確認、勤怠の入力に加えて、チームのチャットチャンネルとカレンダーも合わせて更新します。
書き込みは必ず計画として先に表示され、確認してはじめて送信されます。

- **MCP サーバー** (`packages/mcp`): 通常の HTTP でジョブカンと通信し、構造化されたデータを返します。
- **スキル** (`skills/`): MCP と、エージェントが持つコネクタ(Slack または Teams、Google カレンダー
  または Outlook)を組み合わせ、会社のルールに従います。
- **プリセット** (`preset.example.md`): そのルールと自分の既定値を書く場所です。実際のプリセットは
  `~/.config/jobcan-agent/preset.md` に置き、リポジトリには含めません。

## 安全のための原則

- 書き込みは `confirm=true` を指定するまでドライランで、確認前に必ず計画が表示されます。
- HTTP クライアントがアクセスできるのは、固定で列挙したジョブカンのページだけです(どのモードでも)。
- 認証情報は OS のキーチェーンに置かれ、チャットやモデルを経由しません。
- 会社固有の情報はリポジトリに含めません。

## ジョブカンの利用規約について

ジョブカンの利用規約は、ジョブカンとあなたの会社との間の契約で、あなた個人との契約ではありません。
自動化やスクリプトについての記載はありませんが、サービスの解析や運営に支障をきたすおそれのある行為は
禁止されています([基本規約](https://all.jobcan.ne.jp/terms/) 第9条)。このツールはあなた本人として
ログインし、ブラウザと同じページを読み、リクエストの間隔を空けて動作します。それが許容されるかどうかは、
あなたと、会社でジョブカンを管理している方が判断することです。先に確認してください。

## クイックスタート

必要なもの: macOS(認証情報はキーチェーンから読みます)、Node.js 20 以上、メールアドレスとパスワードで
ログインするジョブカンのアカウント。シングルサインオンや二段階認証は検出して停止します(未対応)。

```bash
git clone https://github.com/clins1994/jobcan-agent.git
cd jobcan-agent
npm install && npm run build
security add-generic-password -s jobcan-mcp -a you@example.com -w   # パスワードを聞かれます
npm run verify -w packages/mcp                                        # ジョブカンへの読み取り専用チェック
```

エージェントにサーバーを登録します。書き込みは有効にしない限りオフです:

```bash
claude mcp add jobcan -- node "$PWD/packages/mcp/dist/index.js"                              # 読み取り専用
claude mcp add jobcan -e JOBCAN_ALLOW_WRITES=1 -- node "$PWD/packages/mcp/dist/index.js"     # 書き込み許可
```

Claude Desktop では `mcpServers.jobcan` に `{"command": "node", "args": ["<repo>/packages/mcp/dist/index.js"],
"env": {"JOBCAN_ALLOW_WRITES": "1"}}` を追加します。

試す: 「有給の残日数を教えて」→「来週金曜に休みを取る計画を立てて」→ 確認。

ここまでで ジョブカンのツールは使えます。チャットとカレンダーの手順を追加するスキルを使うには:

1. [`preset.example.md`](preset.example.md) を `~/.config/jobcan-agent/preset.md` にコピーし、
   チャンネル、そのルール、いつもの勤務時間を記入します。
2. スキルをエージェントから見える場所に置きます。Claude Code なら `~/.claude/skills/` にリンクか
   コピーします:

   ```bash
   for s in skills/*/; do ln -s "$PWD/$s" ~/.claude/skills/; done
   ```

3. プリセットで使うコネクタ(Slack または Teams、Google カレンダーまたは Outlook)をエージェントで
   有効にします。コネクタがなければその手順は飛ばされるだけで、ジョブカンへの申請は止まりません。

その後、新しいセッションで「来週金曜休みたい」や「先月分をバックフィルして」と頼んでください。

## これまでに検証したこと

すべて作者が、このエージェントを作ったセッションの中で、ひとつの会社の実際のジョブカンに対して実行した
ものです。少なくとも一度は最後まで動きましたが、あらゆる環境で保証されているわけではありません。

- メールアドレスとパスワードでのログイン。保存したセッションの再利用。別のログインをしても、ブラウザで
  開いている既存のセッションは切れないこと。
- 読み取り: カレンダー(翌月以降も含む)、休暇種別、残日数、申請一覧、勤怠表、休暇申請フォームの検出
  (項目、理由が必須かどうか、時間のセレクト)。
- 休暇: 全休と時間休(4時間の半休)、過去日付、理由を省略した場合の過去申請からの流用、申請中の
  取り下げ、申請中の時間休から全休への差し替え。
- 勤怠: 1か月分の出勤・退勤(15日・30件)、時間休の前後に合わせた入力。承認待ちの間にもう一度実行
  しても二重に入力しないこと。
- スキル `jobcan-request-leave` を手順どおりに実行: 申請、チャンネルのルールに沿った投稿とリアクション、
  不在イベントの作成。`jobcan-backfill` のもとになった月末の手順も同様に実行: チャットチャンネル・
  カレンダー・ジョブカンの突き合わせ、足りない休暇の申請、勤怠の入力。
- クライアントとジョブカンのページのフェイクに対する 427 件のユニットテスト、実物に対する
  `npm run verify`。

## まだ検証していないこと

- **エンジニアでない人によるセットアップ**: リポジトリのリンクをエージェントに渡して設定を頼み、
  作者の手助けなしに完了すること。
- **新しいセッション**でサーバーを登録しスキルをリンクした状態で、スキル名を指定して呼ぶ、あるいは
  「来週金曜休みたい」「先月分をバックフィルして」とだけ頼むこと。これまでは作者がスキルを手動で進めて
  おり、`jobcan-backfill` はスキルとしては一度も動いていません。
- **`jobcan-setup`**(対話式のプリセット作成)。まだ存在せず、プリセットは手書きです。自分の
  ワークフロー(チャットのみ、カレンダーのみ、先にチャットで連絡して後でジョブカン、いつもの勤務時間)
  を聞き取ってプリセットを書くものにする予定です。
- **他のワークフロー**: カレンダーのみ、チャットのみ、チャットが先。Teams と Outlook(参照ノートは
  ありますが未実行)。
- **他の会社のジョブカン**: 半休の休暇種別、代休・振休、フォームの追加必須項目、理由が任意の設定、
  シングルサインオン、二段階認証。
- **承認後**: 承認済みの勤怠や休暇が勤怠表でどう読めるか。ジョブカンの残日数が承認待ちの申請をすでに
  差し引いているかどうか(差し引いていない前提。ツールは利用可能日数を少なめに見積もることはあっても
  多めに見積もることはありません)。
- **急な休み**: 先にチャットで連絡し、会社の期限内にジョブカンで申請する流れ。
- Claude Desktop にワンクリックで入れる MCPB バンドル、リモート接続、ChatGPT、評価、夜間の読み取り専用
  スモークテスト。

## コントリビューション

いま一番役に立つのは、ご自身のジョブカンでの動作テストです。

- **Issue を開いてください**: 失敗したこと、聞くべきでない質問をされたこと、ページの読み取りが違って
  いたことなど。`npm run verify` の出力と、ツールが表示した計画が一番の手がかりになります。
- **Pull request を開いてください**: 修正や新しいケースに。実際のジョブカンかフェイクか、どのように
  検証して何が起きたかを書いてください。
- **会社の情報は含めないでください**: 会社名、チャンネル名、人名、Slack の ID、休暇種別の名前、名前が
  写ったスクリーンショットは、Issue・PR・フィクスチャに入れないでください。代わりに、見たものの
  「形」を説明してください。
